# 空白画板尺寸输入修复

日期：2026-09-17
范围：`index.html`、`app.js`、`styles.css`（含 `deploy/` 镜像）

## 问题

空白画板弹窗的宽度/高度是**静默夹取**的：

```js
const width = clamp(Math.round(Number(els.blankBoardWidth?.value || 52)), 16, 1000);
```

`clamp()` 会无声改写用户填的数字，且两端都改写：

| 用户填写 | 实际创建 | 用户看到 |
|---|---|---|
| `10` | `16 × 16` | 摘要写 16，没有任何说明 |
| `1` | `16 × 16` | 同上 |
| 滚轮或键入越过 1000 得到的值（如 `5210`） | `1000 × 1000` | 摘要突然变成 1000 |

最后一行正是用户报告「输入 10 却变成 1000」的来源：输入框原值 `52` 未被清空，键入后得到 `5210`，再被夹到上限 1000。
也就是说，用户看到的不是"被抬到下限"，而是"被抬到 1000"——同一个 `clamp` 的另一端。

静默改写的问题不在数值本身，而在于**用户无法察觉自己拿到的是另一个画板**：摘要是唯一线索，
而它和输入框脱节。

## 修复

1. **下限从 16 降到 1**：`min="1"`，`BLANK_BOARD_MIN = 1`。填 1 就创建 1 × 1。
2. **不再夹取**：改为合法性判断 `parseBlankBoardSize()`，只返回 `值 | null`，从不改写输入框内容。
3. **越界即拦下并说明**：摘要显示「尺寸填写有误 · 不会按其他数值创建画板」，输入框标 `aria-invalid`（红框），
   创建按钮禁用，消息区说明 `1 到 1000` 的区间。用户改对之前不会创建出任何"别的尺寸"。
4. **不再有隐式默认值**：清空输入框不会回落到 52，而是按越界处理。

上限保持 1000（1000 × 1000 = 1,000,000 格，已是浏览器可承受的上限附近）。

## 验证

- 单元测试：`node --test smart-preprocessing/*.test.mjs tests/ui-refactor-baseline/*.test.mjs` → **146/146**
- 无头 Chrome 端到端：**16/16**（`docs/evidence/blank-board-size/`）
  - 键入 10×10 / 3×5 / 1×1 / 16×16 / 200×130，落地网格与输入逐项一致
  - 键入 0 / 2000 / 1001：输入框保留原值，按钮禁用，越界字段被标记
  - 清空输入：不回落默认值
  - 预设 78×78 正常回填
  - 1×1 画板下结构替换与旋转仍可用（3×5 → 5×3）
  - 运行期无 JS 异常
