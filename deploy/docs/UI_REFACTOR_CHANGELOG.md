# UI 重构 Phase 2 记录

## 本阶段完成

- 在原有静态页面上接入工作台外壳，不替换原生应用和既有生成算法；旧控件、图库、编辑器与跟做入口保留。
- 新增轻量 Project Store 和生成、色卡、导出适配层，实际生成仍调用原 `processImage()`，最大颜色数传入原有硬约减链路。
- 导入、画布四视图、缩放/平移、视图色号与网格、Inspector、检查及导出抽屉使用当前真实结果。图纸 PNG 的网格、色号、坐标与屏幕开关独立；成品预览 PNG 默认无色号和细网格。
- 修复工作台初次布局未挂载和画布高度问题；在本地浏览器检查了图片导入、生成、视图切换、色号开关、导出抽屉及控制台错误。

## 回归基线

`tests/ui-refactor-baseline/legacy-baseline.json` 是旧页面在浏览器实际生成的固定图纸矩阵摘要，`post-refactor-snapshots.json` 是新页面同参数的捕获。非方形 `images.png` 在 52、78、104 宽下矩阵摘要分别为 `1d2fb1ab`、`343a897e`、`cec80835`；四彩图 `libai-logo.png` 在 52 宽、最大 38 色下为 `37e8a20a`，与旧页面一致。

`node --test smart-preprocessing/*.test.mjs tests/ui-refactor-baseline/*.test.mjs`：41 项通过（原有 37 项及本阶段 4 项）。固定快照测试对比的是已捕获的矩阵，并非每次测试都重新启动浏览器生成。

## 现有约束

- 图片生成高度由原图比例和宽度决定，因此高度在新 Inspector 中只读；不能声称图片模式已有独立宽高生成。
- “色块”视图呈现既有最终颜色网格的无细线渲染，并非另一个可编辑的 Region V2 中间结果。
- 现有编辑器仍有自己的历史记录；本阶段没有把其撤销/重做统一迁移进 Project Store。
- 原引擎的重复生成可能受既有页面状态影响；固定基线按相同初始设置与操作顺序核对。本阶段未调整算法来掩盖该问题。
- 导出只显示底层确有能力的 PNG 与需要分板时的 ZIP；未接入 PDF 或版本化工程文件。
