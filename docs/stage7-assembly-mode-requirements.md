# LIBMS Studio 拼制模式 · 正式需求文档

> 阶段：7（七阶段计划末项「拼制模式规划」）
> 性质：**需求文档**。与《阶段 7：拼制模式规划》（`docs/stage7-assembly-mode-plan.md`）配套 ——
> 规划文档回答「现状是什么、缺口在哪、契约怎么定」，本文档回答「要做什么、做到什么程度、怎么验收」。

## 1. 背景与目标

### 1.1 产品现状（取证结论，详见规划文档 §2）

拼制相关能力在代码里**有三条互不相干的通路**：

| 通路 | 能力 | 入口状态 |
|---|---|---|
| 屏幕施工模式（build 模式） | 区块划分、逐色引导、画布高亮 | 可达（3 处入口） |
| legacy 拼装播放器（`#assembly-modal`） | **逐格打点 + 进度持久化** | **全部不可达**（真机量 box 实测） |
| 导出 / 备料侧 | 板型 ZIP、施工图、材料面板 | 可达，但分块口径与屏幕侧不一致 |

用户今天能得到的「拼制」体验止于：屏幕上把图纸切块、逐块逐色高亮引导。
**没有「拼到哪了」的记录，没有跨会话续拼，没有按块备料，屏幕/导出/备料三处的「块」还不是同一个概念。**

### 1.2 目标

把「拼制」从**一次性引导**升级为**可续、可查、可备料的完整制作流程**：

1. **开始拼制**：从工作台一键进入拼制模式，中途退出再回来不丢位置。
2. **按色号高亮 + 用量可见**：一次只放一色，实时看到「这个色号还要放几颗」。
3. **底板导航**：按实体底板一块一块拼，「下一块拼哪」有明确建议。
4. **进度自动保存**：拼制进度落本地存储，刷新/关机不丢；**与作品图纸数据完全分离**。
5. **与备料打通**：备料与导出和屏幕共用同一套分区，所见即所得。

### 1.3 参考实现对照（bead-grid-studio，仅作设计输入）

参考仓库 https://github.com/zwhy149/bead-grid-studio 的「按色制作助手」与本需求高度同构，其已验证的产品决策直接吸收：

| 参考实现的做法 | 本需求对应条目 |
|---|---|
| 一次突出一个色号，**完成后自动切换下一色** | FR-3 按色号高亮 + FR-6 已完成颜色标记（完成后自动跳下一色） |
| 制作进度**本地保存**，与图纸 JSON 工程分离 | FR-7 自动保存进度 + §5 数据分离硬约束 |
| 材料表导出 CSV 含**完成状态**列 | FR-7（进度可随导出流转，但不回写图纸） |
| 逐格色号 + 底板接缝辅助线 + 用料统计 | FR-2 底板导航 + FR-4 用量显示 |

参考仓库无「按块分区拼制」概念（其底板即接缝线），本需求的「区块」模型保留自有设计（一次性只看一块，更适合大图纸），不照搬。

## 2. 术语与数据契约

### 2.1 契约（一句话）

> **一个作品有且只有一套「分区」（ArtworkSplit），屏幕、导出、备料都读它；拼制进度是挂在分区上的独立数据，永不写进图纸。**

### 2.2 分区模型（实施必建，规划文档 §4.1）

```
ArtworkSplit（唯一分区模型）
├─ boardSize: 52 | 78 | 104          ← 实体底板边长（格），默认 104
├─ source: "board" | "manual"        ← 按实体板分，或用户手选块数
├─ columns, rows, total
└─ blocks[]: { index, row, column, x0, y0, x1, y1, neighbors, usage[] }
```

- 现有 `services/pattern-split-service.js` 的 `splitPatternGrid` 是唯一分区计算归属，**不新建第二个 split 服务**。
- 屏幕 `blockLayout()/blockRect()`、导出 `exportV2.split()`、备料 `renderMaterial()` 三处全部改为读 `ArtworkSplit`（默认参数下行为逐位不变）。

### 2.3 进度数据模型（实施必建， §5 硬约束的落点）

```
AssemblyProgress（独立存储，键：libai-maker-assembly-<作品指纹>）
├─ version: 2                        ← 复用 legacy 播放器键族；v1 为逐格旧 schema
├─ artworkKey                        ← 作品指纹（图纸矩阵 + 色板身份），换图即换进度
├─ split: { boardSize, source, columns, rows, total }
├─ colors: { [paletteId]: { total, done } }        ← 色号级完成标记（FR-6）
├─ blocks: { [index]: "pending" | "active" | "done" }  ← 块级完成标记（FR-2/FR-7）
├─ cells?: { "<x>,<y>": true }        ← 可选：逐格打点（legacy 播放器能力，FR-7 细粒度档）
└─ updatedAt
```

- `paletteId` 是色号唯一身份（**不是 RGB**，同 RGB 不同品牌/套装必须分开计）。
- 进度不进 `state.grid`、不进撤销栈、不进工程文件 `.libms-project` 的图纸字段；
  工程文件若携带进度，只能放在独立字段且默认关闭（避免用一个工程的进度污染另一个）。

## 3. 功能需求

每条需求给出：用户故事 / 需求描述 / 验收标准（可测试）/ 复用对象。

### FR-1 开始拼制

**用户故事**：拼豆爱好者拿到图纸后，想从「看图纸」切换到「照着拼」，中途退出再回来时还在原处。

**需求**：
1. 工作台内提供唯一主入口「开始拼制」（放在左轨「施工模式」与底栏，**不新开一级 Tab、不加顶栏按钮**）。
2. 进入拼制模式 = 现有 build 模式；退出 = 返回编辑。模式切换快照/还原 `view` + `editor` + `ui.activePanel`（现有 `setWorkspaceMode()` 行为保持）。
3. 进入时**自动恢复上次进度**：分区数、当前块、当前色、已完成标记。
4. 拼制模式下画布只允许平移，禁止编辑操作（保持现有 B9 行为）。

**验收标准**：
- A1 进入后 `body` 挂 `ws-output-preview`，退出后恢复编辑态（现有真机断言 C1 保持）。
- A2 分区数设为 6 → 退出再进入仍为 6 → **整页刷新后仍为 6**（修 G2，当前实测刷新回 1）。
- A3 当前块在第 3 块时退出，再进入仍停在第 3 块（当前实测被强制回第 1 块）。
- A4 拼制模式下拖拽画布不产生撤销栈条目（`state.grid` 与历史长度不变）。

**复用**：现有 build 模式全部能力（B1–B9，规划文档 §2.1）；新增仅「进度恢复」与「入口统一」。

### FR-2 底板导航

**用户故事**：大图纸要分多块底板拼，我想知道现在拼第几块、还剩几块、下一块拼哪。

**需求**：
1. 板型选择：52 / 78 / 104 三档实体底板（与 `#tile-size-select` 现有选项一致），默认 104。
2. 分区依据二选一：按板型自动分（`source="board"`）/ 用户手选块数（`source="manual"`，1–64，保持现有）。
3. 区块切换：区块地图 + 上/下一块（现有 block map）。
4. **下一块建议**：利用 `tile.neighbors`（`pattern-split-service.js` 已算出四邻接）按「从左上起步、先右后下」的确定性顺序建议下一块；用户手动选块时可覆盖。
5. 面板显示「第 N / M 块」+ 该块行列范围；**屏幕块数 = 导出板数 = 备料底板数**（修 G1）。

**验收标准**：
- B1 同一作品在 52 板下屏幕显示 4 块、导出的板型 ZIP 为 4 张、材料面板报 4 块底板（当前实测：屏幕 104 口径 1 块 vs 材料面板按 104 算「单块」而 `#tile-size-select` 默认 52 —— G1-b 已存在的用户可见错误必须消除）。
- B2 104×104 作品在 104 板下 `needsSplit=false`，导出口径与屏幕一致（默认档字节级不变）。
- B3 「下一块」建议结果确定（同输入同输出，有单测钉顺序）。
- B4 手选 6 块时，导出与备料同样按这 6 块走（屏幕所见 = 导出所得 = 备料所算）。

**复用**：`blockLayout/blockRect`（改为读 `ArtworkSplit`）、`splitPatternGrid` 的 `neighbors`、`#tile-size-select`。

### FR-3 按色号高亮

**用户故事**：一次只拿一种色号摆豆，屏幕上只让我看到该出现的格子，别被其他颜色干扰。

**需求**：
1. 当前色号高亮：画布上属于当前色号的格子正常显示，其余淡化（现有 `editor.highlightedPaletteId` + 渲染器淡化机制，**不改动**）。
2. 当前块内逐色清单：色号 + 颗数 + 上/下一色（现有 `blockColors/renderBlockColors`），**扩展**为同时给出「本块 N 颗 / 全图 M 颗」双口径（FR-4）。
3. **完成后自动切换下一色**：标记当前色完成后，自动跳到本块下一未完成色（吸收参考仓库的核心交互）。
4. 高亮色选择**不写 `state.grid`**（保持撤销栈干净，现有设计意图不丢）。

**验收标准**：
- C1 选中色号 A 后，画布上 A 的格子可见、非 A 格子透明度降低（现有渲染行为保持）。
- C2 切色不改变图纸矩阵与撤销历史。
- C3 标记本块最后一色完成后，自动跳到下一块的第一色（或提示本块完成，见 FR-6）。

**复用**：`editor.highlightedPaletteId` + 渲染器淡化（B6 已在用）；`blockColors()`。

### FR-4 显示当前色号用量

**用户故事**：摆之前想知道这个色号在这个块里要放几颗、整幅作品一共要放几颗，好一次取够豆。

**需求**：
1. 当前色号读数：「本块 N 颗 · 全图 M 颗」随选色实时更新。
2. 数据来源：`blocks[].usage[]`（按块口径，由 `ArtworkSplit` 派生）+ `buildUsageEntries`（整图口径）。
3. 大图纸下用量计算按签名缓存（现有 `boardSplitSignature/boardSplitCache` 模式），不得随每次 `paint()` 全量重算（500×500 全幅深拷贝约 15ms，规划文档 R2）。

**验收标准**：
- D1 选色后读数与人工数数一致（探针造已知作品，逐色断言）。
- D2 切换区块后读数切换到该块口径。
- D3 500×500 图纸下切块/切色不引入可感知卡顿（交互延迟门槛见 §4.1）。

**复用**：`blockColors()`、`buildUsageEntries`、`boardSplitCache`。

### FR-5 显示剩余豆数

**用户故事**：我录过库存，摆豆时想知道这个色号手里的豆还够不够，不够的要补货。

**需求**：
1. 剩余豆数 = **库存 − 图纸用量**，仅当该色号有库存记录时显示；无库存记录时显示「未录入库存」并提供跳转库存面板（不虚构数字）。
2. 数据来源：现有库存台账（`ui/inventory-panel.js` 的 `InventoryPanel`，含手工录入 / 外部图纸识别 / 补货 / CSV）。
3. 剩余数随「标记已完成颜色」递减（已完成 N 颗 → 剩余再减 N），与 FR-6 联动。
4. **只读**：剩余豆数是库存视角的派生展示，不回写图纸、不回写色板。

**验收标准**：
- E1 有色号库存 200、图纸用量 120 时，面板显示「还需 120 · 剩 80」；标记完成 30 颗后显示「剩 50」。
- E2 无库存记录时不显示具体剩余数，入口可跳到库存面板。
- E3 剩余数计算不修改 `state.grid` 与库存台账本身。

**复用**：`InventoryPanel` / 库存台账（不改其内部）；本需求只增加「按色号读取库存」的接缝。

### FR-6 已完成颜色标记

**用户故事**：一个色号摆完了做个标记，下次进来直接从没摆完的色号开始，别重新数。

**需求**：
1. 在逐色清单上对每个色号提供「标记完成 / 取消完成」操作；块级提供「标记本块完成」。
2. 完成态视觉：清单中该色号打勾置灰，画布上该色格子淡化（已完成的不再吸引注意）。
3. 标记完成后自动跳下一未完成色（FR-3.3）；本块全完成则提示并跳到下一块。
4. 进度分子分母：已完成色号数 / 总色号数 + 已完成块数 / 总块数，双读数。
5. **硬约束：标记完成只写进度数据，绝不修改图纸颜色**（见 §5）。

**验收标准**：
- F1 标记某色完成后，图纸矩阵逐位不变（探针：标记前后导出同一作品的色号矩阵 hash 一致）。
- F2 撤销/重做栈中不出现拼制标记操作（拼制操作不进历史）。
- F3 刷新页面后完成标记保留（进度持久化，FR-7）。
- F4 取消完成可逆，不产生第二个真实数据源。

**复用**：`blockColors/renderBlockColors` 扩展；画布淡化机制（FR-3 同款）。

### FR-7 自动保存制作进度

**用户故事**：拼到一半去忙别的，回来打开网页还能接着拼，不丢任何进度。

**需求**：
1. **自动保存**：每次标记 / 打点后防抖写入本地存储（不要求用户点保存）。
2. **存储键**：`libai-maker-assembly-<作品指纹>`（legacy 播放器既有键族，规划文档 §4.6），schema 升级走 `version` 字段，旧 v1 逐格数据可读取迁移，不静默丢弃。
3. **进度与图纸分离**：作品指纹 = 图纸矩阵 + 色板身份（paletteId 集合）。图纸被编辑后指纹变化 → 进度标记为「可能过期」，进入时提示用户确认是否沿用（不自动套用、不自动清除）。
4. **与 legacy 播放器共用同一份进度**：屏幕侧标记「本块完成」后，播放器打开看到同一进度，反之亦然（进度模型提到可复用层，如 `services/assembly-progress-service.js`，两套 UI 共用，**不得发明第三套**）。
5. **可复位**：提供「重置本作品进度」（二次确认），只清进度不动图纸。
6. 导出 CSV 材料表可含「完成状态」列（吸收参考仓库做法：进度可随导出流转，但不回写图纸）。

**验收标准**：
- G1 打点/标记后刷新页面，进度读数与刷新前一致（当前实测：刷新即丢，规划文档 C4b）。
- G2 进度存储中出现且仅出现一个进度键；不存在第二套进度存储。
- G3 工程文件 `.libms-project` 的图纸字段在拼制前后逐位一致（hash 断言）。
- G4 图纸改动后重新进入，进度被标记「可能过期」并需用户确认。
- G5 重置后进度清零、图纸不变。

**复用**：legacy 播放器 `loadAssemblyProgress/saveAssemblyProgress/resetAssemblyProgress`（`app.js:6502/6512/6700`，真机验证可用）提到 `services/assembly-progress-service.js`；存储键族不变。

### FR-8 入口可达性与遗留实现处置（**前置决策，见 §8**）

**需求**：legacy 拼装播放器（`#assembly-modal`，逐格打点 + 进度）与屏幕 build 模式**保留哪一套**必须是明确决策，不能默认并存：
- 方案 A：保留播放器为细粒度拼制视图 → 屏幕侧补「入口 + 进度读取」（工作量最小）；
- 方案 B：保留屏幕侧为唯一拼制视图 → 把逐格打点搬上屏幕，并按 `ui/legacy-ui-policy.js` 既有机制下线播放器入口。

**验收标准**：决策记录进本文档修订记录；被保留方的入口真机可达（量 box）；被下线方的 DOM 与登记同步清理，无残留死入口。

## 4. 非功能需求

### 4.1 性能（不退化是硬门槛）

- 现有尺寸支持（已核查实际限制）：生成图纸输入 **1–500/边**（`#direct-pattern-width/height`），空白画板 **1–1000/边**（`#blank-board-width/height`）。本需求点名的 52 / 104 / 200 / 300 / 500 **全部在支持范围内**。
- 门槛：冷启动、热启动、交互延迟、内存**维持现有基线**（`tests/palette-performance-guard.test.mjs` 等既有门槛测试继续有效，**不得放宽**）。
- 分区与用量计算按签名缓存（FR-4.3）；500×500 下分块备料全量计算不得进入同步绘制路径。

### 4.2 界面

- 所有用户可见文案**中文**，不出现中英文混合功能名；保留现有品牌配色与设计令牌（`--ds-*` / `--ws-*`），不新造平行变量。
- 不产生功能不可达入口；不因面板收起丢失功能（面板收起仅隐藏展示，不删能力）。
- 不新增一级 Tab / 顶栏按钮（用户已定调「不要复杂、不要占地方」）。

### 4.3 移动端

- 拼制面板与区块地图在 ≤390px 窄屏可用，无横向溢出；触屏可达性（量 box 而非看存在性）。
- 真实触屏与多指手势验收列为后续实施的必过项（当前未验收，不冒充通过）。

### 4.4 数据与算法

- **不动生成/匹配算法路径**：本需求与 `smart-preprocessing/` 无关；`tools/b4-bench.mjs` 冻结基线（`tests/b4-bench-baseline.test.mjs`）必须保持逐位一致。
- 不建立第二套真实色号系统、第二套画板状态、第二套进度存储。
- 确定性：同一作品的同一进度操作序列，落盘结果确定（可单测）。

## 5. 硬约束：拼制进度与作品图纸数据分离

以下四条为**不可协商**的实现红线，任何实施步骤违反即回退：

1. **进度不写图纸**：拼制模式下的任何操作（选块、选色、标记完成、打点、复位进度）都**不得修改 `state.grid` 的任何一个格子**。标记「已完成」只写 `AssemblyProgress`，图纸颜色逐位不变。
2. **进度不进撤销栈**：拼制操作不出现在撤销 / 重做历史里（保持 `ui/workspace.js:3762-3765` 既有设计意图：区块与颜色的选择本来就不写 `state.grid`）。
3. **进度不是工程图纸字段**：`.libms-project` 的图纸矩阵 / 色板 / 图层在拼制前后逐位一致；进度若随工程流转，只能放独立字段且默认关闭。
4. **只有一套进度**：屏幕 build 模式与 legacy 播放器共用同一 `AssemblyProgress`（FR-7.4）；禁止出现第二套进度存储或第二套进度 schema。
