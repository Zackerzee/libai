# 本地融合引擎 V1：源码接缝与实施边界

2026-10-14。目标：先把复杂度移入本地生成流程，验证后取消常驻左侧栏目；本阶段不改变布局，不接外部 API，不上线。

## 已核验的代码

- `services/source-classifier.mjs` 的 `classifySource` 已测量本地图像信号，使用硬规则和候选评分；低置信度返回 auto。它不是能够可靠理解人像/动漫语义的视觉模型，不能宣称完美自动识别。
- `services/generation-pipeline.mjs` 的 `analyzeRoutingEvidence` 和 `runGenerationPipeline` 是现有 V2.5 路由与 runner，可复用而不另建分类真源。
- `smart-preprocessing/generation-engine-v2.mjs` 在采样后进行色卡匹配，随后保护、清理、精修、容差、预算、finalize。完整引擎的采样候选应接在匹配之前，不能拿已量化的最终矩阵再作为 V2.5 源图。
- `src/algorithms/pindou-full/pipeline.mjs` 当前封装整条原生流程，六采样可作为候选能力；该 runner 的量化/refine/remap不能和 V2.5 再串行全跑。
- `app.js` 旧版分支包括 portraitPremium、region-aware 和可选 optimizer。必须评估其独有行为，不能整段当作第三遍清理接入。

## 建议 V1 链路

原始上传图 → 一次几何/色调处理 → 现有本地路由证据 → 命名采样策略（V2.5 或原生候选） → 一次合法色卡匹配/量化路径 → 源图证据及结构保护 → 保守清理/可选精修 → 固定基线智能容差 → 单次保护预算 → 唯一正式 grid。

Worker 请求只传策略名称和纯配置，函数在 Worker 内解析；不能把主线程 lab 函数跨 structuredClone 传递。所有结果继续绑定现有 requestId/源图/参数/色卡，取消和过期结果不得提交。

## 分阶段验证

1. 先做独立可测的融合模块及 named sampler 适配，不改默认生产输出。
2. 比较当前三引擎和融合候选：相同原图、裁剪、尺寸、合法色卡。检查 null、颗数、尺寸、palette身份、确定性、撤销重做和导出一致性。
3. 五尺寸 52/78/104/250/500 实测首次生成、参数变化、主线程长任务和可测内存；失败不能仅凭算法测试通过认定可用。
4. 真实照片、动漫、插画、像素画、文字/Logo、透明图逐类对照；没有样本的类别明确待验收，不用程序合成图片替代真实语义样本。
5. 通过后收成一个用户入口。左栏的参考图、文字、检查、备料等不都是生成算法设置，先规划迁往按需工具/面板，不能直接删除功能。

## 必须守住

保留现有 dirty 修改；不增加第二套可编辑画板；不反复量化；不从平均 RGB 造非法豆色；强制色数预算如牺牲保护要报告；归零调整回到原始基线；色块条不改；现有工程与导出不在审计阶段变更。

本文件是审计与实施计划，不表示融合代码已经开发完成或其画质已经更好。
